## 2. 产品定义

### 2.1 产品目标

**工具 A：UP 主数据查询**
- 目标：给普通玩家、入门 UP 主、二次元爱好者一个免费、顺手、打开即用的 B 站 UP 主/视频数据轻查询入口，解决"竞品 299 元/月起步、轻度查询无处可去"的痛点。

**工具 B：财报营收速查**
- 目标：把散落在新闻资讯里的上市公司游戏财报数据结构化成可查询、可对比的工具页，解决"搜腾讯游戏收入跳出来全是新闻稿、没有结构化速查页"的 SEO 空白。

### 2.2 用户故事

#### 工具 A：UP 主数据查询

| # | 用户故事 |
|---|---|
| A1 | 作为一个 B 站玩家，我想输入某 UP 主的 mid 或昵称直接查到他的粉丝数和最新视频数据，以便快速了解这个 UP 主有多火。 |
| A2 | 作为一个入门 UP 主，我想查某个对标 UP 主的粉丝数和投稿视频的播放/三连数据，以便判断自己内容和同行的差距。 |
| A3 | 作为一个二次元爱好者，我想看某个分区最近的热门视频排行，以便发现值得追的新内容。 |
| A4 | 作为一个内容运营，我想复制一个视频 BV 号查它的播放/弹幕/收藏等统计，以便做内容复盘时快速取数。 |

#### 工具 B：财报营收速查

| # | 用户故事 |
|---|---|
| B1 | 作为一个游戏行业关注者，我想搜"腾讯"直接看到它游戏业务营收和同比增速，以便快速了解头部公司赚多少。 |
| B2 | 作为一个财经博主，我想在一个页面对比几家游戏公司的游戏营收和占比，以便写稿时快速取数不用翻多份财报。 |
| B3 | 作为一个投资者，我想看某游戏公司近几个季度的游戏营收趋势，以便判断其游戏业务是否在增长。 |
| B4 | 作为一个游戏从业者，我想查某公司的游戏营收占总营收的比例，以便评估它对游戏业务的依赖程度。 |

## 3. 技术规范

### 3.1 需求池（P0/P1/P2）

> 标注：[A]=UP 主查询 [B]=财报速查 [S]=共享

#### P0 — MVP 必须做（上线最小可行）

| # | 需求 | 工具 | 说明 |
|---|---|---|---|
| P0-1 | UP 主查询入口页：mid 输入框 + 查询按钮 + 错误提示 | A | 支持精确 mid 查询；昵称模糊搜索见待确认问题 Q1 |
| P0-2 | UP 主详情页：基本信息展示（昵称/头像/签名/等级/认证/VIP/粉丝数/关注数/视频数） | A | 数据来自 `/x/space/wbi/acc/info` + `/x/relation/stat` |
| P0-3 | UP 主详情页：最新投稿视频列表（标题/播放/弹幕/评论/收藏/投币/分享/点赞/发布时间，分页 ≤20 条） | A | 来自 `/x/space/wbi/arc/search` |
| P0-4 | 视频统计查询：输入 BV 号查单条视频统计 | A | 来自视频状态数接口 |

| P0-8 | 公司列表页：按游戏营收降序的公司表格（公司名/代码/游戏营收/同比/占总营收比） | B | 第一版覆盖公司数见待确认 Q2 |
| P0-9 | 公司详情页：基本信息 + 游戏业务营收 + 营收构成（国内/海外或分品类）+ 同比增速 | B | 数据源：公开财报 |

### 3.3 待确认问题（需阿鲲决策）

| # | 问题 | 建议默认 | 理由 |
|---|---|---|---|
| Q1 | UP 主查询第一版是否支持昵称模糊搜索，还是只支持精确 mid 输入？ | 第一版只支持精确 mid，昵称搜索放 P1 | B 站搜索接口需额外 WBI 签名且返回多结果需二次筛选，P0 宁窄勿杂；精确 mid 已覆盖核心查询场景 |
| Q2 | 财报速查第一版覆盖多少家游戏公司？ | 先 12-15 家头部（腾讯/网易/三七互娱/世纪华通/完美世界/吉比特/巨人网络/心动公司/哔哩哔哩/中手游/祖龙/IGG 等） | 覆盖 A 股+港股+美股主要上市游戏公司，SEO 够用且手动维护成本可控 |
| Q3 | 财报数据更新方式：纯手动录入 vs 半自动抓取？ | 第一版手动录入/CSV 导入 Supabase | 财报季度才更新一次，手动维护成本远低于做抓取；后期数据多了再考虑半自动 |
| Q4 | UP 主详情页 ISR revalidate 间隔多久？ | 1 小时 | UP 主粉丝数/视频数据日级变化，1 小时平衡新鲜度与抓取频次；可配置 |
| Q5 | 分区热门视频排行是否纳入 P0？ | 不纳入，放 P1 | P0 聚焦"UP 主+财报"两个最小切片，分区排行单独成页、接口逻辑独立，第二批评估再加 |
| Q6 | 视频统计查询（输入 BV 号）放 UP 主详情页内还是独立成页？ | 放 UP 主详情页底部内嵌 | 减少页面数，P0 不单独成页；独立查询页若需求验证强再拆 |

## 4. 范围边界（明确不做）

| 不做 | 理由 |
|---|---|
| B 站登录态（SESSDATA）相关功能 | 第一版走未登录额度，合规且简化 |
| 硬付费墙 / 订阅功能 | P2 阶段验证，第一版纯免费 |
| 单游戏流水数据 | 无免费稳定数据源（调研报告已论证） |
| 粉丝增长曲线展示 | 数据需积累，第一版只"开始采样"，展示留 P1 |
| 图表库（Recharts/ECharts 等） | 第一版用纯 SVG/CSS bar |
| B 站企业开放平台对接 | 审核周期长、需企业资质，第一版用社区公开接口 |
| 代码实现 / 架构设计 | 本 PRD 只定义需求，实现与架构由架构师/开发负责 |
